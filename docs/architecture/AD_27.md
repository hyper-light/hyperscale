# AD-27: Gate Module Reorganization

**Decision**: Reorganize gate-related code into focused modules following manager patterns.

**Rationale**:
- Current gate.py is monolithic and hard to maintain
- Similar to manager refactoring already completed
- One class per file improves testability
- Clear module boundaries reduce coupling

**Proposed Structure**:
```
hyperscale/distributed_rewrite/
├── jobs/
│   ├── gates/                    # Gate-side job management
│   │   ├── __init__.py
│   │   ├── gate_job_manager.py   # Per-job state and locking
│   │   ├── job_forwarding.py     # Cross-gate job forwarding
│   │   └── consistent_hash.py    # Per-job gate ownership
│   │
│   ├── managers/                 # Manager-side (existing)
│   │   ├── __init__.py
│   │   ├── job_manager.py
│   │   ├── worker_pool.py
│   │   └── workflow_dispatcher.py
│   │
│   └── __init__.py
│
├── datacenters/                  # DC-level coordination
│   ├── __init__.py
│   ├── datacenter_health.py      # DatacenterHealthManager
│   ├── (manager_dispatcher.py)   # removed 2026-10-04: never read; gate
│   │                             #   dispatch is GateDispatchCoordinator
│   └── (lease_manager.py)        # removed 2026-10-06: DC leases never acquired;
│                                 #   at-most-once is leadership + fencing + AD-40
│
├── reliability/                  # Cross-cutting reliability
│   ├── __init__.py
│   ├── retry.py                  # RetryExecutor
│   ├── circuit_breaker.py        # CircuitBreaker
│   ├── load_shedding.py          # LoadShedder
│   ├── backpressure.py           # BackpressureController
│   ├── rate_limiting.py          # rate limiting (sliding windows, AD-24)
│   ├── overload.py               # HybridOverloadDetector
│   └── jitter.py                 # Jitter utilities
│
├── health/                       # Health checking
│   ├── __init__.py
│   ├── worker_health.py          # WorkerHealthState, three-signal model
│   ├── extension_tracker.py      # Adaptive extensions
│   └── (probes.py)               # removed 2026-10-05: never used; health is
│                                 #   the AD-19 three-signal model
│
└── swim/
    └── gates/                    # Gate SWIM extensions
        ├── __init__.py
        └── peer_topology.py      # GatePeerTopology
```

**Migration Plan**:
1. Create new module directories
2. Extract classes one at a time (preserve behavior)
3. Update imports in gate.py incrementally
4. Add tests for each extracted class
5. Final cleanup of gate.py

## Status (2026-10-06)

Steps 1-4 are done; step 5 is not.

- Built: the gate is decomposed into coordinators and handlers under `hyperscale/distributed/nodes/gate/`
  (`dispatch_coordinator.py`, `replication_coordinator.py`, `health_coordinator.py`,
  `job_failover_coordinator.py`, `leadership_coordinator.py`, `orphan_job_coordinator.py`,
  `peer_coordinator.py`, `stats_coordinator.py`, `datacenter_manager_selector.py`, `handlers/tcp_*.py`),
  with gate job state in `jobs/gates/` (`gate_job_manager.py`, `consistent_hash_ring.py`,
  `gate_job_timeout_tracker.py`) and DC health in `datacenters/`. The dead `GateCancellationCoordinator`,
  `GateConfig` and the `if coordinator ... else inline` duplicates are gone.
- Not built: the "final cleanup". `nodes/gate/server.py` is still one `GateServer` class of about 10,100 lines
  (it grew from about 6,900 as functions were split for the complexity ceiling), and still holds business
  logic such as result fencing and best-effort tracking. Moving the remaining domains into composed classes is
  REMAINING_WORK_PLAN Phase 8, not started.
