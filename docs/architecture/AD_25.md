# AD-25: Version Skew Handling

**Decision**: Support rolling upgrades via protocol versioning and capability negotiation.

**Rationale**:
- Zero-downtime upgrades require version compatibility
- Nodes must handle messages from older/newer versions
- Unknown fields should be ignored, not rejected
- Capability advertisement enables gradual feature rollout

**Protocol Versioning**:
```
┌─────────────────────────────────────────────────────────────────┐
│                    Version Skew Handling                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Version Format: MAJOR.MINOR                                    │
│  ├─ MAJOR: Breaking changes (must match)                       │
│  └─ MINOR: Additive changes (newer can talk to older)          │
│                                                                 │
│  Handshake includes:                                            │
│  ├─ protocol_version: "1.2"                                    │
│  ├─ capabilities: ["cancellation", "batched_stats", ...]       │
│  └─ node_version: "hyperscale-0.5.0" (informational)           │
│                                                                 │
│  Compatibility Rules:                                           │
│  ├─ Same MAJOR: compatible                                     │
│  ├─ Different MAJOR: reject connection                         │
│  ├─ Newer MINOR → older: use older's feature set               │
│  └─ Older MINOR → newer: newer ignores unknown capabilities    │
│                                                                 │
│  Message Handling:                                              │
│  ├─ Unknown fields: ignore (forward compatibility)             │
│  ├─ Missing optional fields: use defaults                      │
│  └─ Missing required fields: reject with clear error           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**Implementation**:
```python
@dataclass
class ProtocolVersion:
    major: int
    minor: int

    def is_compatible_with(self, other: "ProtocolVersion") -> bool:
        return self.major == other.major

    def supports_feature(self, other: "ProtocolVersion", feature: str) -> bool:
        """Check if feature is supported by both versions."""
        # Feature was added in version X.Y
        feature_versions = {
            "cancellation": (1, 0),
            "batched_stats": (1, 1),
            "client_reconnection": (1, 2),
            "fence_tokens": (1, 2),
        }
        required = feature_versions.get(feature, (999, 999))
        return (
            (self.major, self.minor) >= required
            and (other.major, other.minor) >= required
        )

@dataclass
class NodeCapabilities:
    protocol_version: ProtocolVersion
    capabilities: set[str]
    node_version: str  # Informational

    def negotiate(self, other: "NodeCapabilities") -> set[str]:
        """Return capabilities supported by both nodes."""
        return self.capabilities & other.capabilities
```

## As built (2026-10)

- **Versions and capabilities** live in `hyperscale/distributed/protocol/` (`protocol_version.py`,
  `node_capabilities.py`, `negotiate_capabilities`). Negotiation runs at manager registration with a gate
  (`nodes/gate/handlers/tcp_manager.py:420`, `nodes/manager/version_skew.py:83`), worker registration
  (`nodes/worker/registration.py`), and client submission (`nodes/client/submission.py:609`). Tests:
  `tests/unit/distributed/protocol/test_version_skew*.py`.
- **Partial:** the manager stores the capabilities negotiated with each gate (`nodes/manager/version_skew.py`),
  but `gate_supports_feature`, `get_gate_capabilities` and the other query methods have no callers, so no
  behavior is yet gated on a negotiated gate feature.
- **Message field evolution** (implemented 2026-10-06): every wire `Message` dataclass pickles its state by
  name. Reading an older sender's message, a field the sender lacked reads as its declared default
  (`Message.__getattr__`, `models/message.py:147`; it runs only when normal lookup fails, so set fields cost
  nothing, and the default is stored on first read). Reading a newer sender's message, unknown fields land in
  the instance `__dict__` and are never read. A field added without a default is never invented: reading it
  raises, naming the field. The pickle format is unchanged, so there is no cutover.
- **Test:** `tests/unit/distributed/models/test_rolling_upgrade_wire_compatibility.py` covers all 104 wire
  messages through the real `Message.load` in both directions, plus the breaking-change case.
